# رسالة البدء لجلسة Claude Code على الحاسوب

انسخ ما بين الخطّين والصقه في Claude Code بعد فتحه داخل مجلد المستودع
(`git pull` على الفرع `claude/awesome-lamport-9qfea2` أولاً).

---

أنت تختبر تطبيق «نبض» (يوميات خاصة، Flutter، أندرويد) على هاتفي الحقيقي الموصول بهذا الحاسوب عبر USB.

المهمة: نفّذ `docs/DEVICE_TEST_PLAN.md` كاملة، قسماً بعد قسم، باستعمال `scripts/device/nabd.sh` (شغّله بلا وسيط ليعرض أوامره). ملف الـAPK هو `nabd-debug-arm64.apk` (سأخبرك بمساره).

قواعد:
1. تحقّق أولاً من `adb` و`nabd.sh devices`. إن لم يظهر الهاتف توقّف واطلب مني تفعيل تصحيح USB وقبول بصمة الحاسوب.
2. قبل `uninstall` أو `clear` أو «الحذف الكامل» أو `reboot` اسألني وانتظر موافقتي. الإزالة تحذف بياناتي.
3. لا تخمّن مكان النقر: `nabd.sh ui` ثم `nabd.sh tap`. خذ لقطة بعد كل خطوة مهمة وانظر إليها فعلاً قبل الحكم.
4. الخطوات التي تحتاج حواسّي (سماع الأصوات، البصمة، الإملاء، رؤية شاشة سوداء، إضافة الأداة) اطلبها مني بسؤال قصير ومحدّد، ثم سجّل جوابي كما هو.
5. لا تعدّل أي كود في المستودع ولا تدفع شيئاً. مخرجاتك كلها في `device-test-output/` (مستثنى من git).
6. بعد كل قسم: `nabd.sh errors` وأضف أي استثناء للتقرير.
7. إن تعطّل التطبيق: اجمع `nabd.sh errors 300`، سجّل خطوات الإعادة، أعد التشغيل وتابع بقية الخطة.
8. اكتب التقرير النهائي في `device-test-output/REPORT.md` بالتنسيق المذكور في آخر الخطة، بالعربية، ثم اعرض عليّ ملخّصه: عدد الخطوات الناجحة/الفاشلة وأهم العيوب.

ابدأ بالقسم 0.

---

بعد انتهاء الجلسة: أرسل `device-test-output/REPORT.md` (واللقطات المهمة) إلى جلسة التطوير لتصلح العيوب.
