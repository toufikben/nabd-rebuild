# تقرير الفحص الشامل لمستودع نبض

**تاريخ الفحص:** 2026-09-22
**المستودع:** `toufikben/nabd-rebuild`
**الفرع:** `main`
**الـ commit المفحوص:** `7493fd8f152391b38755eefaba3d71cbdf54239b` — `fix: restore Android biometric prompt lifecycle`

## الخلاصة التنفيذية

المستودع ليس في مرحلة الصفر. المراحل الأساسية من الإقلاع إلى الميزات الشخصية موجودة فعليًا، ونجح أحدث تشغيل موثق على GitHub Actions في تحليل المشروع وتشغيل الاختبارات وبناء Debug وRelease APK/AAB للـ commit الحالي. لكن **لا يجوز اعتبار التطبيق جاهزًا للإطلاق**؛ لأن هناك حواجز مؤكدة في حماية البيانات، ومسار التصدير، وتحقيق الدخل، وتهيئة iOS، وApp Links، والتوطين.

أهم نتيجة: **خارطة الطريق الحالية صادقة في جوهرها بشأن بقاء R-Data & Security مفتوحة، لكنها قديمة في بعض بيانات التحقق**. فهي تشير إلى commit أقدم وإلى 65 اختبارًا، بينما يثبت CI الحالي على `7493fd8` نجاح **71 اختبارًا**. لذلك يجب تحديث سجل خارطة الطريق بدل الاعتماد على أرقامها القديمة.

## نطاق الفحص وطريقة التحقق

تم فحص شجرة المصدر والوثائق وخطة الطريق وتاريخ Git وملفات Android وiOS والاختبارات ومسارات التهيئة والأمن والتوطين وتحقيق الدخل. كما تم التحقق من أحدث تشغيل GitHub Actions بدل الاكتفاء بسجلات سابقة. لم يكن Flutter SDK مثبتًا في بيئة الفحص المحلية، ولذلك لم أعد تشغيل `flutter analyze` أو `flutter test` محليًا؛ واعتمدت لهذه النتيجة على سجل CI الحالي مع الفحص الساكن المباشر للكود.

تم استخدام إرشادات الكتابة التقنية لإخراج هذا التقرير. لم يتم تعديل كود التطبيق أثناء التدقيق.

## ما تم التحقق من إنجازه

### البناء والاختبارات

أحدث تشغيل موثق هو GitHub Actions run `35734294687` على الـ commit الحالي `7493fd8`. نجحت الوظائف التالية:

| الوظيفة | النتيجة |
|---|---|
| Analyze and test | نجاح؛ `flutter analyze` أظهر `No issues found`، ونجحت 71 اختبارًا |
| Build debug APK and AAB | نجاح |
| Build signed release APK and AAB | نجاح |
| حالة شجرة Git المحلية | نظيفة؛ `git diff --check` لم يسجل أخطاء |

هذا يثبت **قابلية البناء الآلية الحالية**، لكنه لا يثبت سلامة كل سلوك runtime أو جاهزية المتجر.

### الأمن الموجود

يوجد مفتاح Hive بطول 32 بايت محفوظ عبر Secure Storage، وتوجد خدمة AES-256-GCM للنصوص مع nonce وMAC، كما يحتوي BackupService على اشتقاق مفتاح من كلمة مرور ونسخة احتياطية مشفرة وفحوص لمسارات الأرشيف وتكرار المعرفات. توجد اختبارات للتشفير، والهجرة، وتلف MAC، والاستعادة، والحذف.

هذه نقاط جيدة، لكنها تثبت وجود الآلية فقط. لا تثبت اكتمال دورة الحياة على جهاز حقيقي أو أن كل مسارات المنتج تستخدمها بطريقة موحدة.

## أشياء لا يجوز اعتبارها مغلقة رغم وجود اختبارات

اختبارات `backup_security_test.dart` و`database_migration_test.dart` مفيدة، لكنها لا تغطي بصورة كافية سيناريوهات التشغيل التالية:

| السيناريو | الحالة الحالية |
|---|---|
| استعادة backup بكلمة مرور صحيحة وخاطئة على دورة تطبيق كاملة | غير مثبتة على جهاز أو emulator |
| تلف MAC بعد مشاركة الملف وإعادة فتح التطبيق | يوجد اختبار جزئي، لكن لا يوجد تحقق runtime كامل |
| فشل المصادقة الحيوية وعودة التطبيق من الخلفية مع timeout | غير مثبتة على جهاز فعلي |
| تدوير مفتاح مع بيانات حقيقية ثم إعادة فتح التطبيق | غير مثبت؛ والـ API الحالي خطير |
| حذف البيانات ثم التحقق من بقاء/حذف المفتاح وفق السياسة | يوجد اختبار مساعد، لكن القرار المنتجّي غير محسوم نهائيًا |
| App Links وdeep links على Android/iOS | لا يوجد assetlinks أو تحقق جهاز فعلي |
| شراء، استرداد، إلغاء، انتهاء، وتجديد الاشتراكات | لا يوجد تحقق خادمي أو اختبار متجر كامل |

## الحكم النهائي

**الحالة الحالية: جاهز للبناء الآلي، غير جاهز للإطلاق الإنتاجي.**

يمكن اعتبار R-Launch إلى R-Personal منفذة على مستوى وجود الكود ومساراته الأساسية، مع بقاء ديون QA. أما R-Data & Security فهي حاجز حقيقي وليست بندًا تجميليًا. كما أن وجود Release APK/AAB ناجح في CI لا يعالج مشكلة تدوير المفتاح أو التصدير غير المشفر أو entitlement غير الموثوق أو App Links المفقودة.

لا أوصي بفتح إطلاق عام قبل إغلاق البنود الحرجة والعالية في الجدول، ثم تنفيذ مصفوفة Final QA على جهاز أو emulator. بعد ذلك يجب تحديث خارطة الطريق بحيث تشير إلى `7493fd8` وإلى نتيجة 71 اختبارًا بدل السجل القديم.
